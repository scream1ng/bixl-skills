# Independent question rounds

The user prefers **2–3 questions per round**, each answerable without knowing the answers to the others. The purpose is to settle real decisions efficiently, not run a fixed questionnaire.

## Construct a round

1. List what is missing after reading the request and inspecting the inputs.
2. Select up to three decisions with no dependency between them.
3. Make each question self-contained, concise, and specific. For choices, give 2–3 distinct options and identify a recommendation when defensible. Allow a free-text answer.
4. Present the entire round together. Wait for answers before dependent work or the next dependent round; continue useful independent work meanwhile.
5. Incorporate the answers and remove resolved questions. Ask the next round only if another consequential uncertainty remains.

If the supplied brief already settles the decisions, ask nothing. If exactly one necessary issue remains, ask one; do not invent two more. Do not treat silence or an elapsed timeout as approval.

## Example: new product from a photograph

Round 1, only where these are unknown:

1. What output do you need: a visual model/render, dimensioned STEP, or both?
2. What is the overall width or another reliable scale dimension? An approximate value is acceptable for an initial visual concept.
3. Which aspects must closely match the reference: outer shape, feature layout, or both?

After the answers, a mechanical part might need an independent round about its mounting pattern, mating-part clearance, and material. A visual scene instead might need a round about alternate views, finish, and background. Do not ask both branches in advance.

## Dependency example

Do not ask “Which manufacturing process?” and “What injection-molding draft angle?” together when molding has not been selected. Settle the process first; ask process-specific questions in a later round.

Similarly, determine a mounting method before asking for its hole pattern. Independently known overall dimensions and output format can be asked in the same round.

## Changes and approvals

Honor authorization already given. Ask when a proposed fix changes the agreed envelope, a functional interface, the requested scope, or another consequential constraint. State the concrete change and its effect. Batch independent changes together; present a dependent redesign only after its prerequisite decision is answered.
