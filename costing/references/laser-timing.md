# Laser timing and sheet handling

Read this file whenever laser throughput is estimated or revised. Read only the matching entries in `laser-technology.json`. Keep the PDF outside the skill.

## Technology selection

Use current user/CAM/machine technology and measured or programmed times first, then the saved manual lookup, then a labelled fallback. For mild steel, require nitrogen when e-coat is specified, including laser-cut children of an e-coated assembly; otherwise use oxygen unless overridden. Match material, thickness, gas and lens. Multiple technologies at a thickness are alternatives, not additive operations. If lens is unknown, show a provisional selection and its speed sensitivity; never silently select the fastest option. The manual is S235 on a 2500 W Orion; other mild-steel grades are proxies, not validated recipes. Do not change material purchase grade to stainless because nitrogen is selected. Do not borrow another thickness or switch to oxygen when an exact nitrogen entry is absent; flag the gap and use explicit provisional evidence. Stainless/aluminium are uncommon and have no saved technologies here; obtain suitable data if needed.

## Program time

Prefer a user-supplied total program time and output count: program seconds/part = minutes*60/output; program pcs/h = output*60/minutes. Confirm whether this covers one sheet, several sheets, skeleton cuts and handling. Keep known scope separate from unknown scope. Do not add cutting, piercing, travel, lead-ins or skeleton cutting again when included in a total program time.

Otherwise extract flat external and internal cut lengths and pierces from CAD; visually check the flat. Skin-based unfolding is approximate. Allocate contour lengths to fast, medium and slow speeds with an explicit rationale, rather than treating all geometry as full-speed cutting. A provisional slow speed for small holes is an assumption, not a manual classification rule. Cutting seconds = 60*sum(length_mm/speed_mm_min). Include selected piercing routine, applicable preflow, blow and extra time; do not add fast and normal piercing together or choose the shorter routine without evidence. `cut_preflow_raw` has conflicting table units: leave that delay unresolved and disclose its omission until verified. Special fast/advanced routines need actual selected settings; the core lookup does not represent their full time. Add extra lead-in or skeleton cut length only if known or explicitly estimated. Movement/acceleration allowances must have a stated basis and sensitivity; do not automatically add a fixed 3 or 8 seconds per part. An unresolved allowance is not a measured zero.

Use calibration jobs as comparisons, never universal factory multipliers. HUD: 36 parts/32 minutes = 53.333 s/part. Lower bracket: 160/44 = 16.5 s/part. Both are program times excluding handling. Lower bracket's approximate cutting+piercing build-up (16.364 s) is close to its program time, so a blanket extra 3 s/part is inappropriate there. HUD requires more residual time; do not force both jobs to one overhead rule.

## Handling per sheet

Use `rates.json` laser_sheet_handling_minutes_default: **10 minutes TOTAL loading plus unloading per sheet**, user approved, unless overridden. This is neither 10 minutes each nor 10 minutes per part. No automatic 6-second per-part handling charge. Record removal method (whole-sheet/skeleton lift or individual picking). Include extra sorting/separation only when required and outside the handling allowance, avoiding overlap. Include skeleton cutting in program time separately from lifting the skeleton.

Full identical sheets: allocated handling seconds/part = 600/actual parts per sheet; effective pcs/h = 3600/(program seconds/part + allocated handling seconds/part). For one sheet with program P minutes and N parts: effective pcs/h = 60*N/(P+10). Use actual nest output first; otherwise label sheet counts estimated, with a yield scenario. Never treat an illustrative quantity as a verified nest.

Batch costing: charge 10 minutes per sheet actually handled, including a partial final sheet, rather than charging only fractional sheets. For standalone Q and verified N, sheets handled = ceil(Q/N), unless a documented remnant/co-nest plan changes it. Use one `shared_batch` handling row: cost = sheets_handled*(10/60)*applicable hourly rate, separate from the program `process` row; allocate co-nested sheet handling once with shares summing to one. Keep program-only and effective output clearly labelled in notes. A combined process rate is valid only if computed from total batch seconds including whole-sheet handling, with no separate handling cost. Apply laser resource rate for occupied machine time by default; if handling occurs while the machine cuts on an exchange table, document incremental downtime and separate labour/resource ownership rather than charging overlapping machine time twice. The 0.25 h laser batch setup remains separate and must exclude sheet handling already charged.

## Reporting

Retain the authoritative costing tables. Show selected gas, technology, lens, cut length, pierces, program seconds/part, parts/sheet, 10-minute sheet handling basis and program/effective pcs/h in concise notes. Show sheet handling as a separate named cost row if using shared_batch. Gas consumption cost needs confirmed flow/price and confirmation of what the machine rate includes; pressure alone cannot price gas. For an output-rate-only question, report the timing table and assumptions without inventing a full quote or requiring missing grade/finish data.
