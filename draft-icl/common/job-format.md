# Job data (version 1)

Keep `spec.json`, unmodified source CAD/drawings and `geometry.svg` together. Paths in the spec are relative to its directory. Runtime outputs belong here, never inside the installed skill. On a change, increment `revision`; keep check `key` values stable even if displayed IDs change.

Use `examples/bending/spec.json` as a structural example only. Replace its sources/measurements/geometry with the actual job. Required fields:

- `version: 1`, `process: laser|bending|welding`, positive integer `revision`.
- `part`: `number`, `name`, ISO `date`, `drawing_number`, `frequency` (explicit `TBC` when unknown).
- `sources`: objects with relative `path` and full `sha256`. The hash locks the evidence; it does not prove that the measurements are correct.
- `checks`: stable `key`, displayed `id`, `description` without the appended nominal, `gauge`, evidence `source`, practical `method`; optional numeric `nominal`, numeric nonnegative `tolerance`, `unit: mm|deg`, or textual `limits`. Missing limits become `TBC`. Never encode a nominal as a formatted number string.
- Each Laser check has `group: setup|hourly`. Bending defaults to `group: main`. Keep groups in mapped order. The included Laser profile permits up to 3 setup + 8 hourly checks (including the final SOP008 check); Bending permits 8 checks. The exporter compacts unused rows and inserts repeated prototype check rows within this capacity. Extend an inspected profile explicitly when more checks are necessary; never drop checks to fit.
- IDs are derived from ordered checks at load time: L1…Ln, B1…Bn or W1…Wn. Stable keys remain authoritative for dimensions, balloons and comments. After a removal, remove its linked dimensions and balloon references too; `python scripts/icl.py remove-check JOB/spec.json --key STABLE_KEY` performs this edit, increments revision and records history. The configured company final visual check is reapplied on load; disable it in a job-local profile only when explicitly requested.
- Optional check `feature` supplies the short noun (`slot`, `hole`, `thickness`, `distance`, `angle`). `size_checks` is a list of current stable keys, including this check, whose measured nominals form the caption (for example `["slot_width","slot_length"]`). Units must match. Repeat one key for an equal-sided square. Optional `diameter: true` adds Ø. Numeric descriptions/methods remain evidence; printable captions are generated without copied numeric strings. Nominal angles display with one decimal while raw nominals and tolerance precision remain intact.
- Optional job `available_gauges` overrides the included company equipment list after availability is verified. Gauges must match the selected list exactly. Included profiles: Vernier, Protractor, Visual. Add Pin gauge, Micrometer, height gauges or other equipment only with availability and practical contact/access evidence. The SOP008 quality row belongs to the included company Laser profile; other companies should use a job-local profile and their own acceptance reference.
- `drawing`: integer `width`, `height`, relative geometry path and `dimensions`. Geometry root viewBox must be `0 0 WIDTH HEIGHT`. Use only vector shapes/groups with explicit attributes; no text, scripts, styles, links or raster images.
- Dimension: stable check key in `check`, `kind: horizontal|vertical`, physical feature projection points `a` and `b`, dimension-line `offset`, optional numeric label `value_xy`, and separate `badge_xy`. Coordinates use SVG screen axes. Endpoints must come from the selected CAD view and measurement references, not guessed pixels. Rendering does not measure CAD.
- Angular dimension: `kind: angle`, `centre`, positive `radius`, `start_deg`, `end_deg`, `value_xy`, `badge_xy`; the referenced check must have unit `deg`. Angles use SVG screen coordinates; the positive sweep must match the CAD nominal within 0.02 degrees for rounding. Optional `contact_segments` contains exactly two pairs of projected points, one pair on each physical straight surface used by the gauge. Verify both endpoints belong to the finite CAD faces and avoid bend radii; retain `surface_faces` and 3D `contact_points` as job evidence. Rendering alone cannot validate those surfaces.
- Optional `drawing.balloons`: each has `checks` (stable check keys), CAD-projected `target`, off-part `badge_xy`, optional ordered `elbows` from target toward badge, and optional evidence `source_point`/`view`. Labels are derived from check IDs, including several checks at one feature. Anchor on the actual checked feature in the complete overview so detail views can be traced back to the part; repeat balloons for distinct occurrences as needed. All balloons are retained in the exact SVG used for Excel.
- Optional `drawing.views` composes views into the output `width`/`height`. Supply `source_width`/`source_height` matching the geometry SVG viewBox. Each top-level geometry group has `data-view="KEY"`. Each declared view has unique `key`, `source_box:[x,y,width,height]` and nonoverlapping `box:[x,y,width,height]` inside the output canvas. Every dimension and balloon uses a declared `view` key, with projection coordinates inside that source box. The renderer maps geometry and all annotation points with the same aspect-preserving transform, keeping annotation font sizes consistent. Keep each complete CAD view inside its declared source box; inspect unbroken outlines after packing.
- Optional `review_note` appears in the right-hand review card. Use it for job-specific evidence gaps or view limitations, outside the drawing and printable form.
- Optional `layout` points to a job-local layout JSON, which points to its own relative template. Its process must match. Follow the bundled mapping format after inspecting the actual workbook; exporter supports the existing check columns B/C/E/G and a logo plus drawing panel.
- Optional `history` records prior `{date, revision, change, author}` entries. Append the previous revision when editing a job; the current `change`/`author` become the newest row. Do not import an unrelated template part's history.

Each review writes `preview-rN.html` and `drawing-rN.svg`. Approval records bind the current spec, geometry, sources, template, layout and saved preview. Do not edit HTML directly: edit the spec/geometry, bump revision and regenerate. Notes do not mutate nominal values or create an approval.

No measurement acceptance is implied by `TBC`, a matching hash, successful script execution or preview approval. Check the resulting Excel in the target application, including print layout.
