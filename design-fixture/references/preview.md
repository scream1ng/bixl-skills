# Lightweight Three.js preview

`workflow.py concept` writes one user-facing artifact: `preview.html`. It also retains private workflow files (`scene.json`, `evaluated-spec.json`, `concept.step` and review PNGs) for CAD checks and recovery. Do not expose those private files, a ZIP, or multiple review artifacts during concept review. It also runs the cap-joint generator and `audit_width.py`, writing `audit.json` and reporting `cap_joints`, `material_width` and `cross_support` with the other concept statuses, so a 10 mm violation surfaces during concept iteration rather than at the delivery build. No DXF/nesting/final package is produced. Geometry comes from the final pipelines' OCP plate, tab/slot, clamp, checking-offset, body and hardware functions. Block concepts use `block_bodies` with box stock/add/subtract or exact finished STEP, not machining approval.

HTML embeds deterministic gzip-compressed indexed meshes, pinned Three.js 0.180.0 modules from jsDelivr, rotate/pan/zoom, isometric/front/right/top cameras, per-component/group visibility, selected ID, project/revision and a permanent non-authoritative warning. Coarse tessellation and vertex clustering compact workpiece meshes; original/preview triangle counts are recorded. No random triangle omission or mesh measurement is authoritative.

For inline ChatGPT visualization, use an available raw-HTML visualization surface with the **exact generated HTML**, not a local-file iframe. Discover the supported surface; no second skill is required. Aim for at most 850,000 bytes; the generator stops if `preview.html` is not strictly below 1,000,000 bytes. Never bypass the check or substitute a larger attachment. Interactive HTML needs CDN, ES-module, WebGL and `DecompressionStream` support; a failure message appears only when loading fails. Do not claim inline rendering succeeded without inspecting it. Comment mode pins numbered notes to clicked points and records the component ID; Copy comments returns them as text, selecting it for Ctrl+C where the clipboard is blocked. Comments are review notes only and never edit the spec. Window capture is still enough feedback.

Diagnostic CLI: `python scripts/preview.py spec.json OUT --kind weld --construction laser_rib`. Routine projects use `workflow.py concept` to enforce identity. Keep evaluated-spec hash with the scene; never mix revisions. Preview STEP remains private work material, never a substitute for final reopened exports/validation.
