# Lightweight Three.js preview

`workflow.py concept` writes one user-facing artifact: `preview.html`. It also retains private workflow files (`scene.json`, `evaluated-spec.json`, `concept.step` and review PNGs) for CAD checks and recovery. Do not expose those private files, a ZIP, or multiple review artifacts during concept review. No DXF/nesting/final package is produced. Geometry comes from the final pipelines' OCP plate, tab/slot, clamp, checking-offset, body and hardware functions. Block concepts use `block_bodies` with box stock/add/subtract or exact finished STEP, not machining approval.

HTML embeds deterministic gzip-compressed indexed meshes and pinned Three.js 0.180.0 modules from jsDelivr. The default UI contains only the rotatable/pannable/zoomable model and lightweight Workpiece, Fixture and Hardware visibility toggles when those groups exist. Do not add camera presets, component lists, selection tools, project metadata or explanatory/detail panels to the default viewer. Coarse tessellation and vertex clustering compact workpiece meshes; original/preview triangle counts are recorded. No random triangle omission or mesh measurement is authoritative.

For concept review, render the **exact generated HTML** in the available raw-HTML visualization surface, not a local-file iframe. Aim for at most 850,000 bytes; the generator must stop if `preview.html` is not strictly below 1,000,000 bytes. Never bypass the check or substitute a larger attachment. Interactive HTML needs CDN, ES-module, WebGL and `DecompressionStream` support. A failure message appears only when loading fails. Inspect the rendered model before presenting it. Ask for a window capture only when the user identifies a design problem. Keep non-authoritative mesh, clamp-pose and engineering warnings in `project.json` and the private evidence records rather than cluttering the viewer.

Diagnostic CLI: `python scripts/preview.py spec.json OUT --kind weld --construction laser_rib`. Routine projects use `workflow.py concept` to enforce identity. Keep evaluated-spec hash with the scene; never mix revisions. Preview STEP remains private work material, never a substitute for final reopened exports/validation.
